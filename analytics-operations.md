# Analytics Operations (RU/RS/EN)

Документ фиксирует регулярный процесс аналитики конверсий для сайта бюро:
- что трекать;
- какие алерты мониторить;
- какие воронки использовать сейчас (без платного трафика);
- когда смотреть метрики и как принимать решения по правкам.

## 1) Цель аналитики

Цель: управлять конверсией из трафика в заявки, а не просто смотреть посещаемость.

Ключевая бизнес-метрика: количество и доля `qualified leads` по RU/RS/EN.

## 2) Базовые сущности и определения

- `session` — визит пользователя.
- `cta_click` — клик по ключевому CTA ("Обсудить задачу", "Discuss your task" и т.д.).
- `brief_start` — пользователь начал заполнять бриф.
- `brief_submit` — отправка брифа инициирована.
- `brief_success` — сервер подтвердил успешную отправку.
- `brief_error` — сервер/сеть вернули ошибку отправки.
- `contact_click` — клик по прямому контакту (Telegram/email/Viber, когда добавите).
- `raw_lead` — любой входящий лид.
- `qualified_lead` — лид, релевантный data-first услугам бюро.

## 3) Что трекать (MVP-набор)

### 3.1 События (обязательно)

1. `cta_click`
2. `brief_start`
3. `brief_submit`
4. `brief_success`
5. `brief_error`
6. `contact_click`

### 3.2 Параметры каждого события

1. `site_lang` (`ru`, `rs`, `en`)
2. `page_type` (`home`, `services`, `service_page`, `blog`, `post`, `brief`, `contacts`)
3. `page_path`
4. `cta_id` (идентификатор кнопки/блока, где применимо)
5. `device_type` (`desktop`, `mobile`, `tablet`)
6. `utm_source`, `utm_medium`, `utm_campaign` (если есть)
7. `referrer_domain` (если есть)

### 3.3 KPI, за которыми следить

1. `CTA Click Rate` = `cta_click / sessions`
2. `Brief Start Rate` = `brief_start / cta_click`
3. `Brief Completion Rate` = `brief_success / brief_start`
4. `Brief Error Rate` = `brief_error / brief_submit`
5. `Contact Click Rate` = `contact_click / sessions`
6. `Lead Rate` = `brief_success / sessions`
7. `Leads by Language` = `brief_success` по `site_lang`

Примечание: пока без рекламы `CPL` не используем, вместо него смотрим эффективность органики и direct/referral трафика.

## 4) Воронки, которые нужны сейчас (без платного трафика)

### 4.1 Основная воронка заявки

`session -> cta_click -> brief_start -> brief_submit -> brief_success`

Это главная операционная воронка. Любая просадка в одном шаге ведет к приоритетной правке.

### 4.2 Воронка прямого контакта

`session -> contact_click -> (ручная квалификация в CRM/таблице)`

Нужна, чтобы видеть долю пользователей, которые уходят в мессенджеры/почту вместо формы.

### 4.3 Контентная воронка (блог -> лид)

`session on post -> internal click to service/cta -> brief_start -> brief_success`

Нужна для оценки SEO-контента по бизнес-результату, а не по просмотрам.

### 4.4 Языковая воронка

Отдельно по `ru`, `rs`, `en`:
`session -> cta_click -> brief_start -> brief_success`

Нужна, чтобы видеть, где локализация или оффер хуже конвертят.

## 5) Алерты (что должно автоматически сигналить)

Алерты ставятся на отклонение от rolling baseline за 4 недели.

1. `CTA Click Rate` упал более чем на 20% (по любому языку).
2. `Brief Start Rate` упал более чем на 15%.
3. `Brief Completion Rate` упал более чем на 15%.
4. `Brief Error Rate` выше 5% за день или выше 3% три дня подряд.
5. Конверсия `mobile` ниже `desktop` более чем на 30%.
6. Любой язык (`ru`/`rs`/`en`) просел по `Lead Rate` более чем на 25%.
7. Резкий рост трафика без роста `brief_start` (признак нецелевого трафика или сломанного CTA).

## 6) Операционный ритм (закрепленный график)

### Понедельник (20 минут): KPI-дашборд и алерты

Проверить:
1. Все KPI из раздела 3.3 за прошлую неделю.
2. Сработавшие алерты из раздела 5.
3. Техническое здоровье отправки формы (`brief_error`, статусы endpoint).

Результат:
- список проблемных зон по приоритету.

### Среда (30 минут): разбор воронки по языкам и устройствам

Проверить:
1. Основную воронку отдельно по `ru`, `rs`, `en`.
2. Разрез `desktop/mobile/tablet`.
3. Топ страниц входа и их вклад в `brief_start` и `brief_success`.

Результат:
- 1-2 гипотезы "где теряем конверсию и почему".

### Пятница (30 минут): решения по правкам на следующую неделю

Проверить:
1. Что произошло после прошлых изменений.
2. Какие гипотезы подтвердились/не подтвердились.

Результат:
- выбрать 1-2 правки на следующую неделю, каждая с целевой метрикой.

### Последний рабочий день месяца (60 минут): месячный отчет

Собрать:
1. Что выросло/просело по KPI и по каждому языку.
2. Какие изменения дали эффект.
3. Где остались узкие места.

Результат:
- план правок на следующий месяц (контент, CTA, форма, UX, локализация).

## 7) Правило принятия решений по статистике

1. Найти шаг воронки с максимальным падением.
2. Выдвинуть одну проверяемую гипотезу на этот шаг.
3. Внести ограниченный набор изменений (1-2 правки за итерацию).
4. Оценить эффект через 1-2 недели против baseline.
5. Закрепить успешное решение или заменить гипотезу.

## 8) Что фиксировать после каждого цикла

Мини-журнал изменений (можно в отдельной таблице/заметке):
1. Дата.
2. Какая метрика просела/выросла.
3. Какая гипотеза проверялась.
4. Что изменили на сайте.
5. Результат через 7-14 дней.
6. Следующий шаг.

Это защищает от хаотичных правок и накапливает рабочие решения по RU/RS/EN.

## 9) Настройка в Google (GA4 + GTM)

Ниже практический чеклист внедрения через Google Tag Manager.

### 9.1 Что уже сделано в коде

1. Добавлен GTM контейнер в шаблоны сайта (через `site.gtm_container_id`).
2. Добавлен JS-трекинг в `dataLayer` для:
   - `page_context`
   - `cta_click`
   - `contact_click`
   - `brief_start`
   - `brief_submit`
   - `brief_success`
   - `brief_error`
3. Добавлены `site_lang`, `page_type`, `page_path` в контекст событий.

### 9.2 Что нужно сделать вам в Google

1. Создать аккаунт и property в Google Analytics 4.
2. Создать Web Data Stream для домена сайта.
3. Создать контейнер в Google Tag Manager (Web).
4. Вписать ID контейнера GTM в `_config.base.yml`:
   - `gtm_container_id: "GTM-XXXXXXX"`
5. В GTM создать тег `GA4 Configuration`:
   - указать `Measurement ID` из GA4 (формат `G-XXXXXXX`);
   - включить отправку page view.
6. В GTM создать триггеры Custom Event для событий:
   - `cta_click`
   - `contact_click`
   - `brief_start`
   - `brief_submit`
   - `brief_success`
   - `brief_error`
7. На каждый Custom Event создать тег `GA4 Event` с тем же event name.
8. В `Event Parameters` передавать параметры из `dataLayer`:
   - `site_lang`
   - `page_type`
   - `page_path`
   - `cta_id` (для `cta_click`)
   - `contact_channel`/`contact_target` (для `contact_click`)
   - `has_files`, `contact_length`, `task_length` (для `brief_submit`)
9. В GA4 отметить `brief_success` как Conversion.
10. Проверить события в GTM Preview и GA4 Realtime.
11. Опубликовать контейнер GTM.

### 9.3 Что настроить в отчетах GA4

1. Создать Exploration воронки:
   - `session_start -> cta_click -> brief_start -> brief_submit -> brief_success`
2. Создать сравнения по `site_lang`: `ru`, `rs`, `en`.
3. Создать сравнения по устройствам (`device category`).
4. Собрать отдельный виджет по `brief_error` и `brief_error rate`.
5. Сохранить еженедельный KPI-дэшборд под ритм из раздела 6.

### 9.4 Платно это или нет

1. `GA4` для вашего объема сайта обычно бесплатный.
2. `GTM` бесплатный.
3. Платный вариант — `Google Analytics 360` (enterprise), для текущего этапа не нужен.
4. Потенциальные косвенные затраты: время на настройку и поддержку отчетов.
