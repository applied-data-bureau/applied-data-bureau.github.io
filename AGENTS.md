## Что это за проект
Статический мультиязычный сайт на Jekyll (RU/RS/EN) для:
- презентации услуг бюро;
- публикации экспертных материалов и кейсов;
- генерации входящих заявок через контент и SEO.

## Бренд и позиционирование
- Названия:
  - RU: **Бюро прикладных данных**
  - RS: **Biro za primenjene podatke**
  - EN: **Applied Data Bureau**
- Формат: небольшое практичное бюро, фокус на прикладной результат.
- Ключевая идея: **data-first услуги для бизнеса** (автоматизация, обработка данных, интеграции, поддержка legacy).

## Скорректированные цели (после аудита)
1. Не только SEO и контент, но и полноценная конверсионная воронка (контакт -> бриф -> заявка).
2. Удерживать data-first позиционирование, не размывать его случайными услугами без привязки к данным.
3. На каждом языке обеспечить одинаково профессиональную и конверсионную витрину.

## Зафиксированный контекст (важное)
- Проект публичный; backend формы (Cloudflare Worker + Telegram delivery) живет в отдельном закрытом репозитории.
- RU/RS/EN поддерживаются как равноправные публичные версии; для `hreflang x-default` использовать EN-домен.
- Приоритет текущего этапа: улучшения контента, конверсии и качества локализаций, без изменения backend-контракта без согласования.
- Ближайший приоритет: задокументировать свежие проекты (n8n-боты и др.) в виде постов/кейсов, пока детали еще в памяти; это нужно для быстрых ссылок в откликах на фрилансе.
- До масштабирования "бизнесовой" оптимизации сначала закрываем упаковку текущих проектов: тексты, изображения, `og image`, удобные ссылки.

## Деплой
- RU: GitHub Pages.
- RS/EN: Cloudflare Pages.

## Интеграционный контракт (web-brief -> worker -> telegram)
- Публичный сайт (это репо) отвечает только за UI формы и отправку запроса.
- Endpoint формы: `brief_form_endpoint` в `_config.base.yml` (может быть fallback через `brief_form_endpoint_fallback`).
- Backend формы (Cloudflare Worker) вынесен в отдельный **закрытый** репозиторий.
- Контракт запроса: `POST /api/brief` (`multipart/form-data`) с полями `contact`, `task`, `files`, `website`, `form_started_at`, `site_lang`.
- Контракт ответа: JSON `{ ok: true|false, error?: string }`.
- Доставка заявок: Worker -> Telegram Bot API (текст + вложения).
- Если Worker недоступен (например, сетевые ограничения в РФ), фронт обязан показывать fallback: написать в Telegram или отправить через VPN.
- Код воркера и секреты в этот публичный репозиторий не коммитятся.

## Правила работы в чатах
- Считать проект витриной услуг + блогом с SEO-целью и целью лидогенерации.
- Любые правки проверять на совместимость с RU/RS/EN.
- Для языковых задач явно фиксировать, какие рынки затрагиваются: RU, RS, EN.
- Не ставить локально зависимости на ноутбук пользователя без явного запроса.
- На текущем этапе приоритет: правки кода, шаблонов и контента.
- Любые изменения backend-контракта формы сначала согласовывать, потому что backend живет в отдельном закрытом репо.
- Репозиторий публичный: не коммитить критичные данные (ключи, токены, пароли, приватные URL, персональные данные).
- Если неочевидно, критичны ли данные, сначала явно спросить пользователя и только потом коммитить.
