# Контекст проекта для будущих чатов

## Что это за проект
Это статический сайт на Jekyll для презентации услуг «Бюро прикладных данных» и публикации тематических материалов.
Сайт работает как витрина услуг + блог.

## Для чего проект
- Привлекать клиентов через SEO и контент.
- Показывать экспертизу через статьи и кейсы.
- Давать быстрые посадочные страницы под ключевые услуги (боты, данные, n8n, Perl, Jekyll, и т.д.).

## Как это устроено
- Движок: Jekyll 4 (`Gemfile`).
- Шаблоны: `_layouts/` и `_includes/`.
- Главная страница: `index.html`.
- Контент: посты в `_posts/ru` и `_posts/rs`.
- Стили/JS: `assets/` (Bootstrap + кастомные стили).
- Картинки: `img/`.

## Мультиязычность
- Базовая конфигурация: `_config.base.yml`.
- Языковые оверлеи:
  - `_config.ru.yml` (русский рынок).
  - `_config.rs.yml` (сербский рынок).
  - `_config.en.yml` (англоязычный рынок).
- RU, RS и EN версии равнозначны: нет «основного» сайта.
- Версии ориентированы на разные рынки, поэтому контент постов может немного отличаться.
- Текст в шаблонах переключается через `site.lang`.
- Посты разделены по языковым папкам.

## Модель контента
- Каждый материал — файл вида `YYYY-MM-DD-slug.html` в языковой папке `_posts/<lang>/`.
- Используется front matter (`layout`, `title`, `type`, `excerpt`).
- `layout: post` рендерится через `_layouts/post.html`.
- На главной посты выводятся списком; в текущей реализации используется `site.posts` без жесткой фильтрации по языку.

## Сборка и запуск
- Локально (Ruby):
  - `bundle install`
  - RU: `bundle exec jekyll serve --config _config.base.yml,_config.ru.yml`
  - RS: `bundle exec jekyll serve --config _config.base.yml,_config.rs.yml`
- Docker-режим описан в `Dockerfile` (есть готовые команды в комментариях).

## Деплой
- RU: деплой в GitHub Pages (из-за блокировок Cloudflare в РФ).
- EN и RS: деплой в Cloudflare Pages, каждая версия на своем домене.
- В репозитории есть workflow для RU: `.github/workflows/deploy-ru.yml`.

## Как работать с проектом в чатах
- Считать проект Jekyll-сайтом услуг + блога.
- При изменениях проверять, что правки не ломают RU/RS/EN версии.
- Для новых материалов ориентироваться на публикацию в нужных рынках: RU, RS и/или EN (контент может различаться).
- Для задач Codex использовать ветку `codex`.
- Если задача про язык/локализацию, явно уточнять: RU, RS, EN или нужную комбинацию.
